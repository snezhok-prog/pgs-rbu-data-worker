# РБУ: обработка данных через external tasks

Java-сервис разбирает XLSX, проверяет данные, применяет импорт порциями и выполняет контролируемый откат. Тяжёлые операции выполняются во внешнем обработчике; BPMN передаёт идентификаторы дела, файла, профиля и операции.

Реализованы **реклама, торговля и питомец**: разбор и валидация XLSX, импорт РОИВ/ОМСУ, восстановление после сбоя и защищённое удаление импортированных данных. Проверенный объём и ограничения: [контракт операций](docs/contract.md), [состав торговли](docs/trade-scope.md), [протокол приёмки](docs/acceptance.md). Пошаговая проверка через обычный CMD: [инструкция](tools/dev-cli/README.md).

## Структура

- `src/main/java/ru/evolenta/pgs/worker` — общие обработчики и отдельные предметные пакеты `advertising`, `trade`, `pet`.
- `src/main/java/ru/evolenta/server` — Spring-адаптер платформы.
- `src/main/resources` — открытые JSON-правила и маппинг; справочники не зашиты в Base64 внутри BPMN.
- `src/test` — локальные тесты и синтетические файлы.
- `local-runner/pom.xml` — самостоятельная сборка тех же исходников и локальный worker без приватного SDK.
- `pom.xml` — корпоративная Spring-сборка по `business-example-service` Эволенты.
- `scripts` — сборка, тестирование и запуск из обычной CMD.
- `tools/dev-cli` — CMD-клиент приёмочного процесса: загрузка XLSX/документов, отдельный BPMN/topic, запуск worker и проверка результатов.
- `config/worker.dev.properties` — безопасный пример. Настоящие параметры стенда и рабочий журнал хранятся вне Git.
- `plan.md` — текущий объём и состояние проверок.

Исходники единые: `local-runner` компилирует общий пакет непосредственно из `src`, без второй копии бизнес-логики.

## Локальная сборка в Windows

Понадобятся JDK 25 и Apache Maven 3.9.x. Установите их обычным способом и откройте CMD:

```cmd
set "JAVA_HOME=C:\Java\jdk-25"
set "MAVEN_HOME=C:\Tools\apache-maven-3.9.16"
set "PATH=%JAVA_HOME%\bin;%MAVEN_HOME%\bin;%PATH%"
java -version
mvn -version
cd /d C:\Projects\pgs-rbu-data-worker
scripts\build.cmd
```

Команда выполняет `clean verify`: компиляцию, JUnit-тесты, четыре исполняемых набора проверок общей логики/рекламы и упаковку. Ошибка любой проверки завершает сборку ненулевым кодом. Основные тесты больше не требуют ручного вызова Java после успешного `mvn test`.

Быстрый повтор тестов без очистки:

```cmd
scripts\test.cmd
```

Прямой переносимый эквивалент:

```cmd
mvn -B -ntp -f local-runner\pom.xml clean verify
```

Результат: `local-runner/target/classes`, исполняемый JAR и зависимости `local-runner/target/lib`. Сгенерированные файлы в Git не включаются. JUnit-отчёты находятся в `local-runner/target/surefire-reports`; подробные проверки импорта/отката — в отдельной папке `local-runner/target/acceptance-*` каждого запуска.

## Запуск worker на ПК

Сначала подготовьте отдельный topic Camunda, собственные тестовые записи и действительный доступ к API реестров/файлов. Скопируйте пример конфигурации в личный файл, например `C:\PGS\runtime\worker.local.properties`. В нём настройте адреса и разрешённые номера стандартов. Пример по умолчанию обращается к localhost, имеет `writesEnabled=false` и `integrationVerified=false`.

После проверки API-контракта, тестового topic и принадлежности записей задайте необходимые флаги в личной конфигурации и выполните:

```cmd
scripts\run-worker.cmd "C:\PGS\runtime\worker.local.properties"
```

Java опрашивает Camunda и забирает задачи сама; входящий порт к ПК для Camunda не требуется. В CMD видны получение задачи, операция, результат или ошибка. Остановка — `Ctrl+C`. Для продолжения используйте ту же папку `worker.journalDirectory`: удаление журнала способно нарушить безопасный повтор операции.

Обработчик получает XLSX через настроенное файловое API. Файл прикладывается в хранилище ПГС, а в дело записываются его метаданные. Сам XLSX не передаётся массивом в переменной Camunda. Подключение к настоящему DEV и пример BPMN описываются в протоколе проверок соответствующего направления.

Пошаговые команды без Postman для рекламы и торговли приведены в [инструкции CMD-клиента](tools/dev-cli/README.md). Авторизация загрузки на текущем DEV использует Cookie собственной браузерной сессии, вводимый в скрытый запрос CMD; в исходники и конфигурационные файлы он не сохраняется.

`local-single` рассчитан на одного испытательного worker. Для нескольких серверных экземпляров необходимы общий устойчивый журнал, согласованная блокировка и подтверждённые технические повторы.

## Spring и передача Эволенте

Корневая структура соответствует прикладному Spring-сервису Эволенты. Имя сервиса — `business-rbu-data-worker`, имя конфигурации — `sier-business-rbu-data-worker`; родитель и версии SDK указаны в [версии и зависимости](docs/versions.md).

Корпоративная сборка:

```cmd
mvn -B -ntp -f pom.xml clean verify
```

Она требует штатного доступа к приватному Maven Registry Эволенты. Сборка `local-runner` этот доступ не проверяет. CI, ci_settings и Docker взяты из актуального шаблона Эволенты. Включены только два исходных публичных CA-сертификата, которые использует его Dockerfile; SHA-256 сверены. Закрытых ключей, SDK/JAR и параметров с секретами в репозитории нет. GitHub Actions запускает самостоятельные проверки; корпоративный Docker/CI и развёртывание принимаются по правилам целевого репозитория Эволенты.

Полезные результаты для передачи: исходники, зафиксированные версии, контракт операций, правила/маппинг, точечные BPMN, синтетические XLSX, протокол реальных проверок и настройки, которые должен предоставить стенд. Локальный тест не доказывает штатную регистрацию и завершение дела ПГС; это отдельно проверяется на целевом стенде.

## Работа команды

`main` хранит проверенное состояние. Изменения вносятся короткими ветками `feature/...` или `fix/...` с тестами и понятным описанием результата. Для нового направления добавляйте отдельный пакет/ресурсы и сохраняйте единый контракт внешних операций. Результат каждого направления подтверждается отдельными тестами и DEV-протоколом.

В репозиторий не добавляются токены, пароли, SDK/JAR, рабочие журналы, HAR, выгрузки реальных дел и параметры подключения с секретами. Пользовательские `.local.properties` и папки `state`/`runs` исключены из Git.
