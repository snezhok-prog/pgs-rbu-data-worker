# Приёмка общего worker — 29.10.2026

Проверены реклама, торговля и питомец: настоящие external tasks Camunda DEV, Java 25 на испытательном ПК, файловое хранилище ПГС и реальные реестры. Использовался отдельный topic. Прямой deployment Camunda не является штатной публикацией стандарта ПГС.

## Сборка и локальные проверки

- Standalone Maven verify: **142 JUnit-теста**, 0 failures/errors/skips; **204 проверки** четырёх исполняемых наборов.
- CMD-клиент: **534 контрактные проверки** с fake transport. Они не изображают запросы DEV.
- С настоящим SDK скомпилированы **93 исходника общего репозитория** и **92 исходника распакованной серверной поставки**; прошёл **21 платформенный тест**. Все **258 SDK JAR** сверены по SHA-256. В runtime standalone — 12 точных SDK-совпадений и 8 дополнительных библиотек Excel.
- Производственный `SdkFilePgsApi`, настоящий `FileStorageServiceImpl` и `StorageEngineS3Impl` прочитали **39 реально загруженных файлов DEV**. SHA-256 всех файлов совпали; fake storage в этой проверке не использовался.
- Native-шаблоны PET: **7 BPMN, 26 external-task замен, 267 локальных проверок**, 76 старых SHA обработчиков и 5 guarded diff форм. Все исходные ID сохранены, включая 181 ID последнего импорта 47615. Штатная публикация и работа форм не подтверждены.

После унификации имён финальная прямая BPMN с topic `pgs-data-processing-v1` загружена в Camunda DEV: 3 определения, 7 external-task привязок, побайтовое совпадение прочитанного XML. Эта отдельная проверка загрузки не запускала новых процессов и не изменяла реестры. В итоговых интеграционных BPMN/серверных настройках используется то же имя; изолированный CMD-прогон добавляет суффикс запуска.

## Удаление данных DEV

Для отката использовались отдельные собственные импорты. После подтверждённых `APPLIED` и engine `COMPLETED` исходные дела вручную переведены `process → complete` с явного разрешения пользователя. Это подготовка тестовых данных, а не доказательство штатного завершения ПГС. Положительные импорты РОИВ/ОМСУ сохранены для просмотра.

Изменённая после импорта запись и запись активного дела сохранены во всех направлениях. Их точные reference case ID присутствуют в плане. Для AD подтверждена реально сохранённая и searchable ссылка `subservices.xsdData.order.licenseId`. AD/TRADE проверены с финальным флагом родителя и незавершённой подуслугой. На DEV схема `myPetAppeals` не объявляет child `subservices`, поэтому живой PET-сценарий использовал активное корневое дело; конфликт родителя/подуслуги PET покрыт отдельным Java-регрессом. Общая схема ради фикстуры не менялась.

PET отдельно учитывает ранее отсутствовавшие записи, ожидающие строки, блокировки и ошибки. Читаемое время МСК, причины и нулевые остаточные pending/technical errors проверены. Старые AD/TRADE-счётчики `deletedRecords` объединяют подтверждённое отсутствие и DELETE worker: в защищённых сценариях они равны 7 и 1 соответственно; это не число физических DELETE.

Один read timeout подготовки TRADE штатно повторён и завершён. Ранние ошибки подготовки входов не выданы за PASS: два AD-сценария использовали не сохранённую/нештатную ссылку и заменены новым файлом со штатным полем; смешанный PET-файл получил отдельные номера после честного отказа дубликатов. Все действия и исходные результаты сохранены в частном протоколе вне Git.

Сборка образа в CI Эволенты, развёртывание Spring, согласованное промышленное хранение `CheckpointStore`/число реплик и штатная публикация/регистрация/формы/финальные статусы ПГС остаются отдельной приёмкой. Исторические Groovy-журналы и уже запущенные процессы автоматически не мигрируются.
