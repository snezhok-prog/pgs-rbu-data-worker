# business-rbu-data-worker

Прикладной Spring-сервис по актуальному `business-example-service` Эволенты: один poller external tasks, операции разбора и проверки XLSX, импорта и контролируемого удаления данных по рекламе, торговле и питомцу. Общая логика находится в `ru.evolenta.pgs.worker`; адаптеры платформы — в `ru.evolenta.server`.

## Сборка

```sh
mvn -s ci_settings.xml -Pgostech clean verify
```

Используются Java 25, Maven 3.9.16 и штатные переменные CI/доступ к Maven Registry. `.gitlab-ci.yml`, `ci_settings.xml`, Dockerfile и два публичных CA-сертификата взяты из `business-example-service`, commit `b716f78a17540b89b0d883f9079189b9fbeca523`. В CI и Docker изменено имя сервиса/его JAR. Закрытых ключей, credentials, SDK/JAR и параметров рабочего стенда в поставке нет.

## Подключение

1. Создать конфигурацию приложения `sier-business-rbu-data-worker` по штатным правилам платформы. В ней задать `worker.enabled=true` и путь `worker.config-file` к заполненному внешнему файлу настроек.
2. Взять список ключей из `config/worker.server.properties.example`. Требуются точные номера целевых стандартов, внутренний API реестров, HTTPS URL ПГС и совпадающий с BPMN topic. Пустой allowlist и неподтверждённая интеграция блокируют запуск.
3. Сохранить штатный `FileStorageService` и конфигурацию storage engine. `SdkFilePgsApi` читает настоящие метаданные `uploadedFiles`, проверяет ссылку в деле/владельца/путь и использует зарегистрированный SDK engine. Отдельный локальный файловый сервер в серверной поставке не требуется.
4. Подключить согласованное устойчивое хранение `CheckpointStore`. Встроенный `local-single` проверен на одном процессе с сохранённым каталогом и OS-lock; он предназначен для испытаний и не заменяет согласование промышленного хранения/блокировок и числа реплик. Удалять журнал при повторе нельзя.

Технический транспорт берётся из платформенного примера. Результат возвращается только после проверки lease; в Camunda передаются скаляры, полные строки и mutation receipts остаются в журнале worker. Одна порция импорта содержит не более 50 физических CREATE/PATCH.

## Контракт и изменения ПГС

Входы: `mainId`, `collectionName=rbuModulesAppeals.subservices`, `camundaBusinessInfoId`, `rbuDomain=ADVERTISING|TRADE|PET`, `rbuProfile=ROIV|OMSU`, `rbuOperation`, `rbuContractVersion=1`. Полный контракт — [docs/contract.md](docs/contract.md).

Семь точечных BPMN/настроек питомца находятся в [integration/pet](integration/pet/README.md). Они основаны на текущих PSI-настройках, сохраняют исходные ID и штатные действия; вместо тяжёлых скриптов вызывают worker. Изменения исходной/опубликованной структуры представлены guarded diff с SHA предыдущего содержимого. Это интеграционные шаблоны, а не подтверждённая штатная публикация.

## Проверки и граница готовности

[Протокол 29.10.2026](docs/acceptance-20261029.md) разделяет локальные тесты, компиляцию/адаптеры на настоящем SDK и реальные DEV external tasks. Библиотеки и версии — [docs/versions.md](docs/versions.md).

Полная корпоративная Maven-сборка на испытательном ПК остановилась на HTTP 401 при получении приватного parent `core-commons:8.0.7`. Прямая компиляция 93 исходников с реальным SDK и 21 платформенный тест прошли. Поэтому сборка образа в целевом CI, развёртывание Spring-сервиса, промышленное хранение журнала и штатный путь ПГС вплоть до финального статуса остаются обязательными проверками принимающей стороны.

Исторические Groovy-импорты без доверенного журнала нового worker к автоматическому откату не допускаются. Уже запущенные процессы не мигрируются этим пакетом.
